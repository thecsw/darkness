## Self-contained embeds

YouTube and Spotify links use their remote players by default. A site that should
make no provider requests until a visitor chooses to leave can render them as
static, first-party cards instead:

```toml
[website]
embed_mode = "card"
```

The source stays an ordinary standalone Org link. Its label becomes the card
title, while an optional `#+caption` supplies the small authored note:

```org
#+caption: Shin Sakiura · AAAMYYY
[[https://open.spotify.com/track/54BW4qpq5ms4bnzBgiWVOo][NIGHT RUNNING]]
```

Cards contain only semantic HTML and the original outbound link—no iframe,
remote image, script, or stylesheet. YouTube, Spotify track, and Spotify
playlist links receive distinct classes for local styling. Use
`#+attr_darkness: embed-card` before any standalone HTTP(S) link to render the
generic version. Use `#+attr_darkness: embed-remote` on a supported provider
link to explicitly restore its remote player on a card-mode site.

The normal writing workflow can stay link-first. Write standalone YouTube and
Spotify links among the prose, then vendor them when the page is ready:

```sh
darkness misa -vendor-embeds
```

Misa scans Org sources, fetches each provider's metadata and artwork, writes a
colocated TOML manifest, and replaces the original link with the appropriate
`spotify_embed(...)` or `youtube_embed(...)` macro call. Inline prose links are
left alone. To keep a standalone provider link untouched, mark it explicitly:

```org
#+attr_darkness: no-embed-vendor
[[https://youtu.be/example][keep this as a normal link]]
```

Vendoring is best-effort. If provider retrieval fails, Misa still writes a valid
minimal manifest with `needs_manual = true`, preserves the source title and URL,
and rewrites the link. The page therefore remains renderable while clearly
showing what needs to be filled in by hand.

The same command also maintains existing manifests. Before scanning for new
links, it revisits vendored references: complete manifests remain untouched,
while incomplete or `needs_manual = true` manifests are retried. To deliberately
refresh every unlocked manifest as well as vendor new links, run:

```sh
darkness misa -vendor-embeds -force
```

Refreshes fetch real titles, creators, colors, YouTube thumbnails, Spotify
covers, durations, and complete public playlist track lists back into each
colocated TOML and artwork file.

A site can deliberately name a manifest beside its page. Darkness provides
these standard macros, which a project may also redefine explicitly in its
normal `_macros.org` vocabulary:

```org
#+macro: spotify_embed [[embed:$1]]
#+macro: youtube_embed [[embed:$1]]
```

Then the page stays as concise as the rest of the writing:

```org
{{{spotify_embed(running.toml)}}}
```

`running.toml` can begin as only `url = "https://…"`; the snapshot importer
hydrates it in place and writes `running.jpg` beside it. Once hydrated, the
manifest remains the complete per-usage template. Both the manifest and its
artwork stay within the current page directory. An optional
`class = "night-running"` is copied onto the outer embed element for
page-specific CSS without raw HTML.

Ordinary builds never fetch providers; they only read these committed files.
Every TOML file is also a manual authoring surface: edit metadata, reorder or
replace `[[tracks]]`, change the manifest-relative artwork path, or rewrite it
completely. A failed refresh leaves the last good file untouched. A missing
manifest renders an explicit, non-linking “embed manifest unavailable”
placeholder because its original URL is not available to the renderer. Rich
embed links open in a new tab; consumers can size every provider consistently
with a shared CSS variable such as `--embed-width`.

### Manifest control flags

Every manifest generated by Misa begins with commented guidance:

```toml
# Misa control flags (uncomment only when needed):
# locked = true       # never rewrite this file, even with -force
# needs_manual = true # retry incomplete metadata on the next normal vendor run
# If both are true, locked wins.
```

A complete unlocked manifest is treated as cached by a normal
`misa -vendor-embeds` run, so ordinary hand edits are preserved. Running with
`-force` deliberately replaces every complete unlocked manifest with newly
fetched provider data. This is a full refresh rather than a field-by-field
merge: custom titles, colors, artwork choices, classes, and playlist ordering
may all be replaced.

Set `locked = true` when a manifest is handcrafted and Misa must never rewrite
it. Locking also protects it from `-force`; it does not prevent editing the TOML
by hand or rendering it during a normal build.

Set `needs_manual = true` when a manifest is incomplete and Misa should retry it
on the next normal `misa -vendor-embeds` run. Retrieval failures receive this
flag automatically. A successful retry rewrites the completed manifest without
the active flag. If retrieval fails again, the editable fallback remains.

When both are active, `locked` wins: the manifest records that it is incomplete
but opts out of every automatic retry. Remove `locked` later to let a normal
vendoring run try again.

| Manifest state | Normal vendoring run | Vendoring with `-force` |
| --- | --- | --- |
| Complete, unlocked | Preserve as cached | Refresh from provider |
| `needs_manual = true` | Retry provider | Retry provider |
| `locked = true` | Preserve | Preserve |
| Both flags active | Preserve without retry | Preserve without retry |
| URL-only stub | Hydrate from provider | Hydrate from provider |
